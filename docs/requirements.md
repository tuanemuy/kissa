# 要件定義書

## 1. システム概要

地域情報共有・観光システムとして、以下の3つのWebアプリケーションを提供する：

- **編集者向けWebアプリケーション**: コンテンツ作成者が地域と場所を管理するためのアプリケーション
- **来訪者向けWebアプリケーション**: 旅行者が地域と場所を発見し相互作用するためのアプリケーション
- **管理者向けWebアプリケーション**: システムの運用と管理のためのアプリケーション

## 2. ユーザーロールと権限

### 2.1 編集者（コンテンツ作成者）

- 地域を作成・管理できる
- 自身の地域内で場所を作成・管理できる
- 自身の場所に他の編集者を招待して共同編集できる
- 招待された場所を管理できる
- サブスクリプションプランを管理できる
- アカウント設定を管理できる

### 2.2 来訪者（観光客・旅行者）

- 登録なしで地域と場所を閲覧できる
- キーワードと位置情報で地域を検索できる
- 地域をお気に入り登録・ピン留めできる（アカウント必須）
- 場所に写真・コメント付きでチェックインできる（アカウント必須）
- アカウント設定を管理できる（登録済みの場合）

### 2.3 管理者

- システム運用ツールにアクセスできる
- ユーザー、地域、場所を管理できる
- システムパフォーマンスと使用状況を監視できる
- サブスクリプションプランと請求を管理できる

## 3. 機能要件

### 3.1 編集者向けWebアプリケーション

#### 3.1.1 地域管理

- **REQ-E-001**: 編集者は新しい地域を作成できる
- **REQ-E-002**: 編集者は自身の地域を編集できる
- **REQ-E-003**: 編集者は自身の地域を削除できる
- **REQ-E-004**: 地域には名前、説明、位置座標、画像を含める
- **REQ-E-005**: 編集者は地域の可視性（公開/非公開）を設定できる

#### 3.1.2 場所管理

- **REQ-E-006**: 編集者は自身の地域内で場所を作成できる
- **REQ-E-007**: 編集者は所有または編集権限のある場所を編集できる
- **REQ-E-008**: 編集者は自身の場所を削除できる
- **REQ-E-009**: 場所には名前、説明、カテゴリ、住所、座標、連絡先、営業時間、画像を含める
- **REQ-E-010**: 編集者は場所の可視性（公開/非公開）を設定できる
- **REQ-E-024**: 編集者は地域の詳細情報（名前、説明、画像、座標）を更新できる
- **REQ-E-025**: 編集者は場所の詳細情報（名前、説明、カテゴリ、住所、座標、連絡先、営業時間、画像）を更新できる

#### 3.1.3 共同編集管理

- **REQ-E-011**: 編集者は自身の場所に他の編集者を招待できる
- **REQ-E-012**: 編集者は編集権限を取り消すことができる
- **REQ-E-013**: 招待された編集者は招待通知を受け取る
- **REQ-E-014**: 招待された編集者は招待を承諾または拒否できる

#### 3.1.4 サブスクリプション管理

- **REQ-E-015**: 編集者は現在のサブスクリプションプランを確認できる
- **REQ-E-016**: 編集者はサブスクリプションをアップグレード/ダウングレードできる
- **REQ-E-017**: 編集者は請求履歴を確認できる
- **REQ-E-018**: システムはサブスクリプション制限（地域数、場所数など）を強制する

#### 3.1.5 アカウント管理

- **REQ-E-019**: 編集者はメールアドレスとパスワードで登録できる
- **REQ-E-020**: 編集者はプロフィール情報（名前、アバター、連絡先）を更新できる
- **REQ-E-021**: 編集者はパスワードを変更できる
- **REQ-E-022**: 編集者はアカウントを削除できる
- **REQ-E-023**: 編集者は通知設定（メール、プッシュ通知）を管理できる

### 3.2 来訪者向けWebアプリケーション

#### 3.2.1 地域発見

- **REQ-V-001**: 来訪者は公開地域の一覧をログインなしで閲覧できる
- **REQ-V-002**: 来訪者はキーワードで地域をログインなしで検索できる
- **REQ-V-003**: 来訪者は位置情報・座標で地域をログインなしで検索できる
- **REQ-V-004**: 来訪者は地域の詳細をログインなしで閲覧できる
- **REQ-V-005**: 登録済み来訪者は地域をお気に入り登録できる
- **REQ-V-006**: 登録済み来訪者は地域をピン留めしてクイックアクセスできる

#### 3.2.2 場所発見

- **REQ-V-007**: 来訪者は地域内の場所をログインなしで閲覧できる
- **REQ-V-008**: 来訪者は場所を地図上でログインなしで閲覧できる
- **REQ-V-009**: 来訪者は場所の詳細をログインなしで閲覧できる
- **REQ-V-010**: 来訪者はカテゴリで場所をログインなしでフィルタリングできる
- **REQ-V-011**: 登録済み来訪者は場所をお気に入り登録できる
- **REQ-V-021**: 登録済み来訪者は地域・場所のお気に入り登録を解除できる

#### 3.2.3 チェックインシステム

- **REQ-V-012**: 登録済み来訪者は場所にチェックインできる
- **REQ-V-013**: チェックインにはタイムスタンプ、任意の写真、任意のコメントを含める
- **REQ-V-014**: 来訪者は自身のチェックイン履歴を閲覧できる
- **REQ-V-015**: 来訪者は自身のチェックインを編集または削除できる

#### 3.2.4 アカウント管理

- **REQ-V-016**: 来訪者はメールアドレスとパスワードで登録できる
- **REQ-V-017**: 来訪者はプロフィール情報（名前、アバター、旅行履歴）を更新できる
- **REQ-V-018**: 来訪者はパスワードを変更できる
- **REQ-V-019**: 来訪者はアカウントを削除できる
- **REQ-V-020**: 来訪者は通知設定（メール、プッシュ通知）を管理できる

### 3.3 管理者向けWebアプリケーション

#### 3.3.1 システム管理

- **REQ-A-001**: 管理者はシステム統計を閲覧できる
- **REQ-A-002**: 管理者はユーザーアカウント（停止、復旧、削除）を管理できる
- **REQ-A-003**: 管理者はコンテンツ（地域、場所、チェックイン）をモデレートできる
- **REQ-A-004**: 管理者はサブスクリプションプランを管理できる
- **REQ-A-005**: 管理者は請求と収益レポートを閲覧できる
- **REQ-A-006**: 管理者はユーザーアカウントのアクセス制御（権限変更、一時停止）を実行できる
- **REQ-A-007**: 管理者はGDPR準拠のためのユーザーデータ完全削除を実行できる

## 4. 非機能要件

### 4.1 パフォーマンス

- **REQ-NF-001**: システムは最大10,000人の同時接続ユーザーをサポートする
- **REQ-NF-002**: ページ読み込み時間は3秒以内である
- **REQ-NF-003**: API応答時間は95%のリクエストで500ms以内である
- **REQ-NF-004**: 画像アップロードは30秒以内に完了する

### 4.2 セキュリティ

- **REQ-NF-005**: すべてのユーザーパスワードはbcryptまたは同等の方法でハッシュ化する
- **REQ-NF-006**: すべてのAPIエンドポイントはHTTPSを使用する
- **REQ-NF-007**: ユーザーセッションは24時間の非アクティブ後に期限切れとなる
- **REQ-NF-008**: ファイルアップロードは種類とサイズを検証する
- **REQ-NF-009**: システムはSQLインジェクションとXSS攻撃から保護する

### 4.3 可用性

- **REQ-NF-010**: システムは99.9%の稼働率を持つ
- **REQ-NF-011**: システムは24時間ごとに自動バックアップを行う
- **REQ-NF-012**: システムは障害から1時間以内に復旧できる

### 4.4 スケーラビリティ

- **REQ-NF-013**: システムは水平スケールが可能である
- **REQ-NF-014**: データベースは読み取りレプリカをサポートする
- **REQ-NF-015**: システムは静的アセット用のCDNをサポートする

### 4.5 ユーザビリティ

- **REQ-NF-016**: システムはレスポンシブでモバイルデバイスで動作する
- **REQ-NF-017**: システムは日本語と英語をサポートする
- **REQ-NF-018**: システムはアクセシブル（WCAG 2.1 AA準拠）である
- **REQ-NF-019**: システムはモダンブラウザ（Chrome、Firefox、Safari、Edge）で動作する

### 4.6 データ

- **REQ-NF-020**: ユーザーデータは毎日バックアップされる
- **REQ-NF-021**: ユーザー個人データは削除可能である（GDPR準拠）
- **REQ-NF-022**: 画像ファイルはWeb配信用に最適化される
- **REQ-NF-023**: 地理座標はWGS84形式を使用する
- **REQ-NF-024**: ユーザーセッションは適切な期限管理により自動的に期限切れとなる

## 5. ビジネスルール

### 5.1 サブスクリプション制限

- **BR-001**: 無料プランは編集者1人につき地域1つ、場所10個まで許可する
- **BR-002**: ベーシックプランは編集者1人につき地域5つ、場所100個まで許可する
- **BR-003**: プレミアムプランは編集者1人につき地域と場所を無制限に許可する

### 5.2 コンテンツモデレーション

- **BR-004**: すべてのユーザー生成コンテンツ（地域、場所、チェックイン）は公開後にモデレートされる
- **BR-005**: 不適切なコンテンツは24時間以内に削除される
- **BR-006**: コンテンツポリシーに3回以上違反するユーザーは自動的に停止される
- **BR-007a**: エディターが作成した地域・場所は即座に公開され、事後モデレーションの対象となる

### 5.3 データ保持

- **BR-008**: ユーザーアカウントデータは削除後7年間監査目的で保持される
- **BR-009**: チェックインデータは2年後に匿名化される
- **BR-010**: システムログは1年間保持される

## 6. 統合要件

### 6.1 地図

- **REQ-INT-001**: システムは地図サービス（Google Mapsまたは同等）と統合する
- **REQ-INT-002**: システムはジオコーディングと逆ジオコーディングをサポートする

### 6.2 決済

- **REQ-INT-003**: システムは決済プロセッサー（Stripeまたは同等）と統合する
- **REQ-INT-004**: システムはサブスクリプション課金をサポートする

### 6.3 ストレージ

- **REQ-INT-005**: システムは画像とファイル用のクラウドストレージを使用する
- **REQ-INT-006**: システムは画像のリサイズと最適化をサポートする

### 6.4 通知

- **REQ-INT-007**: システムはメール通知（招待、モデレーション結果、システム通知）をサポートする
- **REQ-INT-008**: システムはモバイル向けプッシュ通知（リアルタイム通知）をサポートする
- **REQ-INT-009**: システムは通知設定管理（有効/無効、頻度設定）をサポートする

## 7. データモデル

### 7.1 主要エンティティ

#### User（ユーザー）

- id: UUID
- email: string (unique)
- password_hash: string
- role: enum (editor, visitor, admin)
- profile: JSON (name, avatar, preferences)
- subscription_plan: enum (free, basic, premium)
- created_at: timestamp
- updated_at: timestamp

#### Region（地域）

- id: UUID
- name: string
- description: text
- creator_id: UUID (foreign key to User)
- location: geography (coordinates)
- images: JSON array
- visibility: enum (public, private)
- created_at: timestamp
- updated_at: timestamp

#### Location（場所）

- id: UUID
- name: string
- description: text
- category: string
- region_id: UUID (foreign key to Region)
- address: string
- coordinates: geography
- contact_info: JSON
- operating_hours: JSON
- images: JSON array
- visibility: enum (public, private)
- created_at: timestamp
- updated_at: timestamp

#### LocationEditor（場所編集者）

- id: UUID
- location_id: UUID (foreign key to Location)
- editor_id: UUID (foreign key to User)
- permissions: JSON
- invited_at: timestamp
- accepted_at: timestamp

#### CheckIn（チェックイン）

- id: UUID
- user_id: UUID (foreign key to User)
- location_id: UUID (foreign key to Location)
- timestamp: timestamp
- photo_url: string (optional)
- comment: text (optional)
- created_at: timestamp

#### Favorite（お気に入り）

- id: UUID
- user_id: UUID (foreign key to User)
- target_id: UUID (region_id or location_id)
- target_type: enum (region, location)
- created_at: timestamp

## 8. 技術制約

- **TECH-001**: システムはTypeScriptを使用して構築する
- **TECH-002**: フロントエンドはReact 19とNext.js 15を使用する
- **TECH-003**: バックエンドはヘキサゴナルアーキテクチャを使用する
- **TECH-004**: データベースはDrizzle ORMを使用したSQLiteを使用する
- **TECH-005**: エラーハンドリングはResult型（neverthrow）を使用する
- **TECH-006**: すべての関数はResult<T, E>型を返す
- **TECH-007**: テストは形式手法モデルを検証する
